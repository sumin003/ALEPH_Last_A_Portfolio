# 우수민 포트폴리오 갱신 장치

Python 3.10 이상과 표준 라이브러리만 사용합니다. 추가 설치·로그인·API 키·네트워크 연결이 필요 없습니다. Windows에서는 아래 `python` 대신 `py -3`, macOS 또는 Linux에서는 `python3`를 사용할 수 있습니다. ZIP을 푼 폴더에서 실행하세요.

## 실행 방법 세 단계

### 1 입력 파일을 input 폴더에 넣습니다

- `ritual.json`: 리추얼 내보내기 JSON을 이 이름으로 저장합니다. `days` 배열의 `date`, `open`, `close`를 읽습니다. 원본의 시작·마무리 배열과, 포함된 예시처럼 기록 유무를 나타내는 불리언을 모두 지원합니다. 원본은 개인 컴퓨터에만 두세요.
- `tasks.json`: 선정 과제 목록을 갱신합니다. `id`는 T03 형태, `date`는 YYYY-MM 또는 YYYY-MM-DD, `ability`는 자기조절력·대인관계력·자기동기력 중 하나입니다. `status`는 `completed`, `in_progress`, `planned` 중 하나입니다. 전체 제출 목록이 아니면 제출률로 해석하지 않습니다.
- `attendance.json`: 실제 출석 자료를 확인한 경우에만 `attended_days`, `scheduled_days`, `as_of`를 적습니다. 원자료가 없으면 두 숫자를 모두 `null`로 둡니다. 날짜는 YYYY-MM-DD입니다.
- `approvals.json`: 승인한 후보의 ID와 내용 해시를 보관합니다. 처음에는 `{"approved": []}`입니다.

동봉한 리추얼 입력은 `ritual-history-2026-10-30(1).json`에서 날짜별 시작·마무리 기록 유무와 규칙에 의한 능력 분류만 남긴 공개용 입력입니다. 원문과 동료 이름은 포함하지 않습니다. 과제 목록은 이력서에 선정한 T03·T05·T06·T09·T10 다섯 과제입니다. 출석 원자료는 없어 비워 두었습니다.

### 2 후보를 생성하고 읽은 뒤 승인합니다

```bash
python refresh.py generate --input input --output output
```

`output/candidates.json`에서 능력·문장·날짜·근거를 읽고, 사실에 맞고 공개할 문장만 선택합니다. 선택한 후보의 실제 ID를 아래 명령에 넣으세요. 이 명령 실행 자체가 사용자의 승인 행동입니다.

```bash
python refresh.py approve --input input --output output --id 선택한후보ID
```

승인할 후보가 없으면 승인 명령을 생략합니다. 둘 이상이면 `--id`를 반복할 수 있습니다. 승인을 취소하려면 `input/approvals.json`에서 해당 항목을 지웁니다. 후보가 바뀌었으면 기존 항목을 지운 뒤 다시 생성·검토·승인하세요. 도구는 내용 해시가 맞지 않는 승인을 거절합니다.

능력 분류는 본인 경험·회고 필드의 관련 낱말을 찾는 단순 규칙입니다. 능력 점수를 측정하거나 새 사건을 추론하지 않습니다. 사적인 원문을 복사하지 않는 짧은 문장 후보를 만듭니다. 기존 카드 1 이야기는 유지하며, 승인한 새 후보는 별도 ‘승인한 새 기록’ 영역에 추가합니다.

### 3 사이트를 갱신하고 확인합니다

```bash
python refresh.py build --input input --output output --site site
```

`site/index.html`을 브라우저에서 열어 숫자와 승인 문장을 확인합니다. 만족하면 **site 폴더 안의 파일만** GitHub 저장소 루트에 복사해 커밋합니다. 연결된 Vercel이 배포합니다. 장치는 로컬 파일을 만들며 GitHub 업로드나 배포까지 자동 수행하지 않습니다. 개인 원본이 있는 input 폴더는 업로드하지 않습니다.

이 ZIP의 최초 결과는 새 후보 승인 0건입니다. 승인 시험으로 만든 문장을 실제 사용자 승인으로 간주하지 않습니다.

## 같은 입력 두 번 실행 확인

```bash
python verify.py
```

새 임시 폴더에 소스·입력·사이트를 복사한 뒤 위 명령으로 두 번 생성합니다. `output`과 `site`의 모든 파일에 대해 SHA-256을 비교합니다. 불일치하거나 승인·입력 검증이 실패하면 0이 아닌 종료 코드로 끝납니다. 결과는 `verification/comparison.json`에 남습니다. 날짜별 기록을 순서대로 정렬하고 실행 시각·무작위 수·AI 호출을 사용하지 않아 같은 입력에 같은 바이트가 나옵니다.

## 파일 위치

| 위치 | 내용 |
| --- | --- |
| `refresh.py` | 집계·후보 생성·승인·사이트 반영 소스 |
| `verify.py` | 새 폴더 실행, 반복 결과 비교, 승인 동작 검증 |
| `input/` | 리추얼·선정 과제·출석·승인 파일 |
| `output/summary.json` | 마지막 숫자 집계와 출처 |
| `output/candidates.json` | 날짜·근거가 붙은 미승인 문단 후보 |
| `output/site-data.json` | 숫자와 승인한 문장만 담은 공개 결과 |
| `output/approval-status.json` | 후보 수와 승인 수 |
| `site/` | 로그인 없이 볼 수 있는 정적 사이트 사본 |
| `documents/` | 이력서·자기소개서·경력기술서 Word 문서 |
| `verification/` | 반복 실행 비교와 개인정보 점검 결과 |
| `제출안내.txt` | 확인 방법과 AI와 나의 판단 |

## 개인정보와 공개 범위

본인 이름과 공개 이메일만 연락 정보로 사용했습니다. 동료 이름과 리추얼 원문은 동봉하지 않습니다. 공개 논문 사본에서는 참고문헌의 개인 저자명을 생략하고 발행처·제목·연도를 유지했으며, 개인 이름이 든 원문 경로 두 곳은 기관 홈페이지로 표시했습니다. 원래 논문 파일은 수정하지 않았습니다.

자동 점검은 알려진 이름·연락처·비밀값 패턴을 확인하는 보조 수단입니다. 새로운 원본의 개인정보를 완벽하게 알아내는 기능은 아닙니다. 새 파일이나 문장을 직접 추가했다면 공개 전에 본문·문서 속성과 링크를 확인하세요.

현재 원자료의 기록 기간은 2026-08-11~2026-10-30이며 54일, 마무리 기록 47일, 기록이 있는 달력주 12주입니다. 달력주는 월~일 기준이며 공식 13주 과정의 전체 출석·완료를 뜻하지 않습니다. 과제 5건은 선정한 목록의 완료 건수입니다. 13번 앱 공개일과 첫·마지막 문장의 직접 작성 및 동료의 독후 확인은 사용자 확인이 남아 있습니다.
